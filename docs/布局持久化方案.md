# 桌面图标布局持久化方案

本文记录「重启 / 修改刷新率后布局变乱」的根因、`IconLayouts` 二进制的实测结构，以及两套修复方案。
方案 A 已在当前版本实现；方案 B 是后续可直接落地的备用方案。

## 1. 现象与根因

现象：

- 应用布局后，重启有时保持、有时变乱。
- 修改显示器刷新率后布局可能变乱。

根因：

1. `IFolderView::SelectAndPositionItems` 只更新 Explorer 当前桌面视图的内存状态，不落盘。
2. `IShellView::SaveViewState` 的文档定义是“把视图设置写入视图流（GetViewStateStream）”，
   用于后续浏览会话恢复；它不保证桌面图标坐标被可靠写入 `IconLayouts`。
   调用返回成功 ≠ 注册表已保存新坐标。
3. 修改刷新率 / 分辨率 / 显示器拓扑会触发 `WM_DISPLAYCHANGE`，Explorer 会重建桌面视图；
   Windows 10/11 没有稳定的第三方布局锁，重建时可能重新排布图标，并把乱序结果回写注册表，
   覆盖之前的正确布局。
4. 因此“只应用一次、然后指望 Windows 自己保存”的方案天然不稳定，同类工具
   （DesktopOK、ReIcon）都采用“登录后 / 显示变化后重新放回坐标”的做法。

## 2. IconLayouts 实测结构（Windows 10 22H2，131 个图标）

注册表位置：

```
HKCU\Software\Microsoft\Windows\Shell\Bags\1\Desktop
```

值 `IconLayouts`（REG_BINARY）结构：

```
0x00..0x20   头部；0x18 处为 u32 条目数 count
0x20..       名称表，共 count 条：
               u32 字符数（含结尾 NUL）
               u32 保留（0）
               UTF-16LE 名称，例如 "Krita.lnk>  "、"Krita.lnk> |"、"::{CLSID}>  "
名称表之后   60 字节布局头
             表 1：count × 10 字节 { f32 列, f32 行, u16 名称索引 }   （默认/排序用网格）
             中间表：count × 18 字节（含义未解析，改写时保持原样）
             表 2：count × 10 字节 { f32 列, f32 行, u16 名称索引 }   （当前坐标，固定在值末尾）
```

关键结论：

- 注册表存的是**网格行列号**（float32），不是像素坐标。
- 像素换算：`x = origin_x + col * spacing_x`，`y = origin_y + row * spacing_y`。
- 本机实测 `origin = (18, 2)`、`spacing = (75, 91)`；用 131 个图标的真实坐标逐项校验，
  131/131 全部吻合。
- 表 2 的 `名称索引` 指向名称表；表 2 是整个二进制值的最后 `count × 10` 字节。
- `>` 之后是分组后缀，匹配图标时只取 `>` 之前的文件名或 CLSID。

## 3. 方案 A：注册表直写（已实现）

目的：在应用布局后，把本次坐标主动写进 `IconLayouts`，不依赖 `SaveViewState`。

流程：

1. 应用布局前读取当前 `IconLayouts`，解析名称表与末尾坐标表。
2. 按“文件名 / CLSID”把桌面项映射到名称索引；同名项用旧坐标做二次消歧。
3. 用“旧像素坐标 + 注册表网格坐标”拟合网格的 `origin` 与 `spacing`（逐轴最小斜率中位数），
   要求至少 80% 的样本偏差在 3px 内，否则判定注册表与当前视图不同步，跳过直写。
4. 图标移动完成后，用目标像素坐标反算 `col / row`，按名称索引 patch 表 2。
5. 把完整二进制写回注册表；失败只记 warning，不影响布局应用。

实现位置：

- `src-tauri/src/desktop/layout.rs`：坐标表定位、校验、读取、patch。
- `src-tauri/src/desktop/registry.rs`：`write_icon_layouts()`。
- `src-tauri/src/desktop/apply.rs`：原点推导、名称映射、应用后同步。
- 前端 toast 会追加「布局已写回注册表」。

限制：

- Explorer 运行时仍持有自己的内存布局；它后续保存、启动或显示模式变化时仍可能覆盖我们的写入。
- 因此方案 A 只是“让盘上留有一份正确布局”，不能 100% 保证重启/刷新率变化后不被重排。

## 4. 方案 B：隐藏守护（未实现，后续可直接采用）

目标：Windows 把布局弄乱之后，由一个常驻的轻量进程把坐标再放回去。

### 4.1 形态

- 同一个 exe 的 `--guard` 模式：在 `main()` 里先判断参数，
  命中则进入纯 Rust 消息循环并直接返回，不启动 Tauri、不创建 WebView 窗口。
- 进程常驻但无界面，内存占用约 10–20MB。
- 用命名互斥体保证单实例（例如 `Global\DesktopIconBackupGuard`）。

### 4.2 状态

- 在应用配置目录新增 `state.json`：
  ```json
  { "activeBackupId": "...", "scaleMode": "current", "updatedAt": "..." }
  ```
- GUI 每次成功应用布局后更新该文件；守护进程只读。
- 备份根目录沿用 `settings.json` 的 `storageMode / customPath` 解析逻辑。

### 4.3 登录自启

- 写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`：
  `"<exe 完整路径>" --guard`
- 设置页提供「开机自动恢复布局」开关，关闭时删除该 Run 值。
- 不需要管理员权限，不写计划任务。

### 4.4 登录恢复

1. 等待 Explorer 就绪：轮询 `open_desktop_view()`，直到桌面 `ItemCount > 0`；
2. 再延时 5–10 秒，等显示驱动 / DPI 稳定；
3. 读取 `state.json` 指向的备份，复用现有 `apply` 逻辑放回坐标；
4. 校验：重新读取桌面项坐标，与目标偏差超过阈值则重试（最多 2 次）。

### 4.5 显示变化与 Explorer 重启

- 用 `CreateWindowExW` 创建隐藏窗口（或 message-only 窗口），在 WndProc 中监听：
  - `WM_DISPLAYCHANGE (0x007E)`
  - `WM_SETTINGCHANGE (0x001A)`（工作区 / 显示相关变更）
- 收到事件后 debounce 2–3 秒，再执行一次 4.4 的恢复流程。
- 另用 1–2 秒一次的轻量轮询检测桌面 ShellView 的 HWND 是否变化；
  变化说明 Explorer 重启过，同样 debounce 后恢复。
- 不做定时强制重放，避免和用户手动拖动图标打架。

### 4.6 多显示器 / 缩放

- 复用现有 `apply_backup` 的比例换算：`ratio = 当前缩放 / 备份缩放`
  （`scaleMode = "backup"` 时 ratio 取 1.0）。
- 贴边裁剪需要把 `DisplayInfo.virtual_bounds.x / y` 纳入计算，
  当前实现只用了宽高，多屏负坐标场景需要修正。

### 4.7 日志

- 守护进程写 `guard.log`（按大小滚动），记录启动、恢复结果、失败原因，便于现场排查。
- GUI 不弹窗打扰；恢复失败只在日志中记录。

### 4.8 实施清单

1. `tauri.conf.json` / 打包配置：确认 `--guard` 模式随主 exe 一起发布（同一二进制即可）。
2. `src-tauri/src/bin` 或 `lib.rs` 增加 `guard` 模块：互斥体、消息窗口、WndProc、恢复调度。
3. `main.rs`：参数分流，`--guard` 时不进入 `run()`。
4. `apply` 成功后写 `state.json`。
5. 设置页新增开关，联动 Run 注册表值；新增多语言文案。
6. 冒烟测试：登录恢复、改刷新率、结束并重启 Explorer、多显示器接入。

## 5. 验证方法

1. 应用布局后，用 `reg query HKCU\Software\Microsoft\Windows\Shell\Bags\1\Desktop /v IconLayouts`
   导出二进制，按第 2 节结构检查末尾坐标表是否与目标网格一致。
2. 重启一次，观察布局是否保持（方案 A 只能尽量保证，方案 B 才能兜底）。
3. 在 60Hz / 高刷新率之间切换，观察是否变乱（方案 A 预期仍可能乱，方案 B 解决）。
4. 任务管理器结束 `explorer.exe` 后重新启动，观察布局恢复情况。
