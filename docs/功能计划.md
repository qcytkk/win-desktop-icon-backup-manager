# 桌面图标备份管理器 · 功能计划 v0.1

**目标**：实现「一键备份当前桌面图标布局 → 列表管理备份 → 预览布局」的完整闭环。

**架构**：Tauri 2（Rust）负责 Windows 侧数据采集：显示器分辨率/DPI、桌面图标枚举、图标坐标、注册表原始二进制；Vue 3（TypeScript）负责界面、备份列表与布局可视化。每份备份 = 一个 `meta.json` + 一个 `layout.bin`，本地落盘，不联网。

**技术栈**：Tauri 2 / Rust（`windows`、`serde`、`image`）、Vue 3 + TypeScript + Vite + Pinia。

**本期范围**：仅 F1 备份、F2 备份列表、F3 布局预览。不含恢复、自动备份、托盘常驻。

---

## 1. 需求规格

| 编号 | 功能 | 一句话验收 |
|---|---|---|
| F1 | 备份当前布局 | 点击按钮后生成一份含「分辨率 + 全部图标 + 坐标 + 时间 + 数量」的备份，名称可编辑 |
| F2 | 备份列表 | 已备份项以卡片/行两种形态展示，可一键切换视图 |
| F3 | 预览布局 | 点击列表项弹出按原分辨率等比缩放的桌面布局预览 |

### 1.1 F1 备份

**入口**：主界面右上角主按钮「备份当前布局」。

**执行流程**：
1. 读取当前显示信息：主屏宽高、DPI、缩放比、全部显示器矩形、虚拟桌面边界。
2. 枚举桌面 Shell 项：名称、显示名、类型（文件/快捷方式/网址/系统图标）、坐标。
3. 读取 `HKCU\Software\Microsoft\Windows\Shell\Bags\1\Desktop` 全部值，原始字节一并保存（为后续「恢复」功能留数据基础）。
4. 生成默认名称：`备份 2026-11-03 14:32`。
5. 落盘并返回完整记录，列表头部插入新卡片。
6. 轻提示：`已备份 57 个图标`。

**规则**：
- 时间显示格式固定 `YYYY-MM-DD HH:mm`；存储用带时区的 RFC3339。
- 名称默认自动生成，创建后在列表内可直接编辑；长度上限 40 字符，去首尾空格，空值回退到默认名称。
- 备份过程中按钮进入 loading 且不可重复点击。
- 桌面为空时允许备份，提示「当前桌面没有图标」。
- 读取失败（注册表不可读 / Shell 枚举失败）时给出明确错误，不生成半成品备份。

**验收**：
- [ ] 连续点击两次只产生一份备份。
- [ ] 备份记录中的图标数量与桌面实际可见图标数一致。
- [ ] 断网、重启应用后备份仍存在。
- [ ] 名称修改后重启应用仍保持。

### 1.2 F2 备份列表

**入口**：主界面内容区，默认网格视图。

**视图切换**：工具栏右侧分段控件 `网格 / 列表`，切换即时生效，偏好写入 `localStorage`（key：`ui.viewMode`）。

**网格视图**：
- 自适应列宽，卡片最小宽 240px，间距 16px。
- 卡片内容：16:9 缩略布局预览（复用 F3 渲染组件，只读小尺寸）+ 名称 + 元信息（时间 · 分辨率 · 图标数）。
- 悬停显示「预览」与「重命名」两个轻量操作。

**列表视图**：
- 单行 64px 高，列：缩略图 / 名称 / 备份时间 / 分辨率 / 图标数 / 操作。
- 表头固定，滚动区域只滚动内容。

**通用规则**：
- 排序：按备份时间倒序，固定不可改（本期不做排序菜单）。
- 点击卡片或行主体 → 打开预览（F3）。
- 重命名：行内编辑，`Enter` 或失焦保存，`Esc` 取消，失败回滚。
- 空态：居中插画 + 「还没有备份」+ 「备份当前布局」按钮。
- 加载态：首次进入显示骨架屏，不闪白屏。

**验收**：
- [ ] 切换视图后刷新页面仍保持上次选择。
- [ ] 20 份备份时列表滚动流畅，卡片不重排。
- [ ] 重命名立即反映在两种视图与预览弹窗标题中。
- [ ] 空态按钮可直接触发 F1。

### 1.3 F3 布局预览

**入口**：点击备份卡片 / 列表行。

**展示**：全屏遮罩 + 居中弹窗（最大 1200×800，随窗口自适应）。

**弹窗内容**：
- 顶部信息条：名称（可直接编辑）、备份时间、分辨率 `2560×1440 @150%`、图标数。
- 画布：按备份分辨率等比缩放，居中留白；背景为浅色桌面底 + 点状网格。
- 图标：按坐标绝对定位，缩放到画布比例；下方显示截断后的显示名（最多 8 个字符，超出省略）。
- 悬停图标显示完整名称与坐标 tooltip。
- 关闭：右上角 `×`、`Esc`、点击遮罩。

**坐标处理**：
- 使用虚拟桌面边界归一化，支持副屏负坐标。
- 坐标超出备份分辨率范围的图标，钳制到画布内并标记为「异常位置」（半透明 + 虚线边框）。

**降级**：
- 若某份备份未能采集到坐标（技术预研失败路径），预览改为「按名称网格排列」，顶部显示橙色提示条「该备份未记录图标位置」。

**验收**：
- [ ] 预览布局与真实桌面布局在相对位置上一致（肉眼比对）。
- [ ] 131 个图标渲染无明显卡顿（首帧 < 200ms）。
- [ ] 窗口缩放时画布等比缩放，图标不重叠错位。
- [ ] `Esc` 可关闭，遮罩点击可关闭，弹窗内点击不关闭。

## 3. 数据模型

### 3.1 存储位置

```
%APPDATA%\com.liang.desktopiconbackup\
├─ backups\
│   └─ <uuid>\
│       ├─ meta.json      # 元信息 + 图标数组（含坐标）
│       └─ layout.bin     # IconLayouts 原始字节，供后续恢复使用
└─ icons\
    └─ <hash>.png         # 去重后的图标位图缓存
```

### 3.2 meta.json

```json
{
  "schemaVersion": 1,
  "id": "0f1c7a2e-...",
  "name": "工作布局",
  "createdAt": "2026-11-03T14:32:05+08:00",
  "display": {
    "width": 2560,
    "height": 1440,
    "dpi": 144,
    "scaleFactor": 1.5,
    "virtualBounds": { "x": 0, "y": 0, "width": 2560, "height": 1440 },
    "monitors": [
      { "x": 0, "y": 0, "width": 2560, "height": 1440, "primary": true }
    ]
  },
  "iconCount": 131,
  "layoutSource": "folder_view",
  "warnings": [],
  "icons": [
    {
      "index": 0,
      "rawName": "::{645FF040-5081-101B-9F08-00AA002F954E}>  ",
      "displayName": "回收站",
      "kind": "system",
      "x": 24,
      "y": 16,
      "iconKey": "icons/a1b2c3.png"
    },
    {
      "index": 1,
      "rawName": "Krita.lnk>  ",
      "displayName": "Krita",
      "kind": "shortcut",
      "x": 24,
      "y": 96,
      "iconKey": "icons/d4e5f6.png"
    }
  ]
}
```

字段说明：
- `layoutSource`：`folder_view`（Shell COM 读取）/ `icon_layouts`（二进制解析）/ `name_only`（仅名称，无坐标）。
- `warnings`：采集阶段的非致命问题，如「3 个图标未取到位置」。
- `iconKey`：相对存储根目录的图标缓存路径，可为 `null`（回退为文字占位块）。
- `index`：作为渲染唯一键，不使用名称（桌面可能有重名）。

### 3.3 类型定义（前后端共用语义）

```ts
export type ViewMode = 'grid' | 'list'
export type IconKind = 'file' | 'folder' | 'shortcut' | 'url' | 'system'
export type LayoutSource = 'folder_view' | 'icon_layouts' | 'name_only'

export interface DisplayInfo {
  width: number
  height: number
  dpi: number
  scaleFactor: number
  virtualBounds: { x: number; y: number; width: number; height: number }
  monitors: Array<{ x: number; y: number; width: number; height: number; primary: boolean }>
}

export interface IconItem {
  index: number
  rawName: string
  displayName: string
  kind: IconKind
  x: number
  y: number
  iconKey: string | null
}

export interface BackupRecord {
  id: string
  name: string
  createdAt: string
  display: DisplayInfo
  iconCount: number
  layoutSource: LayoutSource
  warnings: string[]
  icons: IconItem[]
}
```

## 4. 技术方案

### 4.1 后端模块

```
src-tauri/src/
├─ lib.rs                 # Tauri builder、命令注册
├─ commands.rs            # 所有 #[tauri::command]
├─ desktop/
│   ├─ mod.rs
│   ├─ display.rs         # 分辨率 / DPI / 虚拟桌面边界
│   ├─ icons.rs           # 桌面项枚举 + 图标 PNG 提取 + 缓存
│   ├─ registry.rs        # 读取 Bags\1\Desktop 全部值
│   └─ layout.rs          # 坐标来源适配 + IconLayouts 解析
└─ storage/
    ├─ mod.rs
    └─ backup.rs           # 创建 / 列表 / 读取 / 重命名
```

### 4.2 IPC 接口

```rust
#[tauri::command] fn create_backup(app: AppHandle, name: Option<String>) -> Result<BackupRecord, String>
#[tauri::command] fn list_backups(app: AppHandle) -> Result<Vec<BackupRecord>, String>
#[tauri::command] fn get_backup(app: AppHandle, id: String) -> Result<BackupRecord, String>
#[tauri::command] fn rename_backup(app: AppHandle, id: String, name: String) -> Result<BackupRecord, String>
#[tauri::command] fn load_icons(app: AppHandle, id: String) -> Result<HashMap<String, String>, String>
```

- `list_backups` 直接返回完整记录（131 个图标约 10KB，30 份备份约 300KB，可接受），网格卡片缩略图直接用坐标渲染，无需额外文件。
- `load_icons` 返回 `iconKey → base64 data URL`，前端存 Pinia，避免重复读取磁盘；缩略图不加载位图，仅用色块占位，进入预览时才批量加载。
- 所有错误统一为 `Result<_, String>`，前端展示中文错误文案。

### 4.3 采集实现要点

**分辨率 / DPI**
- `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)` 取主屏。
- `EnumDisplayMonitors` + `GetMonitorInfoW` 取全部显示器与虚拟边界。
- `GetDpiForMonitor(MDT_EFFECTIVE_DPI)` 取 DPI；`scaleFactor = dpi / 96`。

**桌面项枚举**
- `SHGetDesktopFolder` → `IEnumIDList` → `IShellItem2`。
- 名称：`IShellFolder::GetDisplayNameOf(SHGDN_NORMAL)`。
- 类型：按扩展名 `.lnk/.url` 与 CLSID 判断。
- 系统图标 CLSID 映射：回收站 `{645FF040-...}`、此电脑 `{20D04FE0-...}`、网络 `{F02C1A0D-...}`、控制面板 `{5399E694-...}`。

**坐标（本期最高风险，见第 6 节）**
- 优先级 A：`IShellWindows` 找桌面 `IFolderView` → `GetItemPosition`。
- 优先级 B：解析 `IconLayouts`（名称表已确认结构，坐标段待补齐）。
- 兜底 C：`name_only`，预览按网格排布。

**注册表**
- `RegOpenKeyExW` + `RegEnumValueW` 遍历 `Bags\1\Desktop`，保存值名、类型、原始字节。
- Win11 关键值：`IconLayouts`、`FFlags`、`Mode`、`IconSize`、`Sort`。
- Win10 兼容：额外收集 `ItemPos*` 值。

**图标提取**
- `IShellItemImageFactory::GetImage(SIZE{32,32}, SIIGBF_ICONONLY)` → `HBITMAP` → RGBA → PNG。
- 缓存键：`sha1(displayName + rawName)`。
- 首次备份 131 个图标预计 1–2 秒，之后命中缓存接近瞬时。

## 5. 关键前提（已在本机验证）

- 路径：`HKCU\Software\Microsoft\Windows\Shell\Bags\1\Desktop`。
- 本机（Win11，2560×1440）实测存在 `IconLayouts`（REG_BINARY，11988 字节），无 `ItemPos*`。
- `IconLayouts` 前半段为名称表，结构已确认：

  ```
  [u32 字符数(含 \0)][u32 0][UTF-16 名称 + ">" + 空格 + \0]
  ```

  本机共 131 条，可 100% 解析。名称中的 `>` 与尾随空格是格式自带后缀，展示前需裁剪。
- 坐标段位于名称表之后，微软未公开格式，需通过预研补齐；备份无论如何都会保存原始二进制，不影响后续恢复功能。
- Win10 使用 `ItemPos<宽>x<高>(<DPI>)`，本期做只读兼容，不做坐标写入。

## 6. 技术预研（P0，必须先于功能开发完成）

**目标**：确认能否稳定拿到 131 个桌面项的坐标，并确定 `layoutSource` 的实际取值。

**步骤**：
1. 写最小 Rust 程序（`src-tauri/src/bin/probe.rs`），输出 JSON：`{display, icons:[{name,x,y}], source}`。
2. 路径 A 验证：`IShellWindows::FindWindowSW(SWC_DESKTOP)` → `IServiceProvider` → `IShellBrowser` → `IShellView` → `IFolderView::GetItemPosition`。
3. 路径 B 验证：继续逆向 `IconLayouts` 坐标段，以路径 A 的结果作为真值比对。
4. 判定标准：随机抽取 5 个图标，坐标与桌面上实际位置误差 ≤ 图标网格半步。
5. 记录 Windows 版本（`RtlGetVersion`）与结果，写入 `docs/probe-result.md`。

**决策规则**：
- A 成功 → 采用 A，`layoutSource = "folder_view"`。
- A 失败且 B 成功 → 采用 B，`layoutSource = "icon_layouts"`。
- 均失败 → 本期降级为 `name_only`，预览按网格排列，同时在计划中标记恢复功能受阻。

## 附录 A：恢复布局与图标匹配规则（v0.2 设计预留，本期不实现）

### A.1 匹配身份

- 主键：Shell 解析路径（文件 / 文件夹 / zip / exe / lnk 的完整路径）；系统图标使用 CLSID。
- 辅键：`displayName`，仅在路径不可用时兜底。
- 不读取文件内容、不复制任何桌面文件；匹配为哈希查表，131 项实测可在 1ms 内完成。
- 可选增强：NTFS File ID（卷序列号 + 文件 ID），同盘改名 / 移动仍可匹配；跨盘移动或删除重建后失效。

### A.2 三类结果

| 类别 | 定义 | 处理 |
|---|---|---|
| 已匹配 | 备份有、当前桌面有 | 写回备份坐标 |
| 缺失 | 备份有、当前桌面无 | 跳过，界面标记 |
| 新增 | 备份无、当前桌面有 | 按 A.3 设置处理 |

### A.3 新增项处理（设置项，默认「放到空位」）

1. **放到空位（默认）**
   - 从第一个空网格位开始，按列优先、从上到下填充。
   - 不覆盖已恢复图标，不删除任何新增项。
   - 当前列满后向右开新列，超出主屏范围时进入下一屏。

2. **移入整理文件夹（可选，用户显式开启）**
   - 仅在桌面存在新增项时创建 `桌面图标布局未分配文件_YYYYMMDD_HHmm` 文件夹；重名追加 `_2`。
   - 只移动真实文件系统项；系统 / 虚拟图标（此电脑、回收站、网络、控制面板等）跳过并在结果中说明。
   - 执行前弹出确认，列出数量与名称，明确提示会改变文件在桌面上的实际位置。
   - 写入 `move-log.json`（原路径 → 新路径），恢复面板提供「撤销本次整理」。
   - 移动完成后再生成合并布局，避免整理文件夹内容再次参与布局计算。

### A.4 界面提示

- **预览页**：缺失图标加虚线幽灵框 + 「缺失」角标；顶部提示「备份中有 N 个图标在当前桌面不存在」，并显示新增数量。
- **恢复前确认**：可恢复 X 个 / 缺失 Y 个 / 新增 Z 个。
- **恢复后结果**：成功数量 + 缺失清单 + 新增处理方式 + 撤销整理入口。

### A.5 写入顺序

1. 枚举当前桌面项，建立「路径 / CLSID → 坐标」哈希表。
2. 分类：已匹配 / 缺失 / 新增。
3. 若启用整理文件夹，先移动新增项，再重新枚举桌面。
4. 生成合并布局：已匹配用备份坐标，未分配的放空位。
5. 停止 `explorer.exe`。
6. 写入合并后的 `IconLayouts`（Win10 为 `ItemPos*`）。
7. 启动 `explorer.exe`，返回结果摘要。

> 性能结论：匹配本身不是瓶颈；真正耗时的是移动文件，因此整理文件夹只在用户主动选择时执行。
