# 版本管理与发布流程

## 仓库

- GitHub：<https://github.com/qcytkk/win-desktop-icon-backup-manager>
- 本仓库同时托管源码、Release 安装包与更新日志。

## 版本号规则

采用语义化版本 `MAJOR.MINOR.PATCH`：

- `MAJOR`：不兼容的大改动（例如数据格式不兼容）。
- `MINOR`：向后兼容的新功能（本版 0.3.0 属于此类）。
- `PATCH`：向后兼容的修复。

**每次升级必须同步修改以下三处，缺一不可：**

| 文件 | 字段 |
|---|---|
| `package.json` | `version` |
| `src-tauri/Cargo.toml` | `[package] version` |
| `src-tauri/tauri.conf.json` | `version` |

提交前用下面命令确认三处一致：

```powershell
node -p "require('./package.json').version"
Select-String '"version"' src-tauri/tauri.conf.json
Select-String '^version' src-tauri/Cargo.toml
```

## 更新日志

- 遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。
- 每次发版在 `CHANGELOG.md` 顶部新增 `## [x.y.z] - YYYY-MM-DD`：
  - `新增`：新功能
  - `修复`：缺陷修复
  - `变更`：行为调整
- 文末补齐版本对比链接。

## 发布流程

1. 完成开发，跑通检查：
   ```powershell
   cd src-tauri
   cargo check --all-targets
   cargo test --lib
   cd ..
   npm run build
   ```
2. 更新三处版本号与 `CHANGELOG.md`。
3. 构建安装包与便携版：
   ```powershell
   npm run tauri build
   ```
   产物：
   - `src-tauri/target/release/bundle/nsis/<productName>_<版本>_x64-setup.exe`
   - `src-tauri/target/release/desktop-icon-backup.exe`
4. **重命名为纯 ASCII**（GitHub 会自动改写中文文件名）：
   - `desktop-icon-backup_<版本>_x64-setup.exe`
   - `desktop-icon-backup_<版本>_portable.exe`
5. 复制到 `发布/` 目录留档。
6. 提交并打标签：
   ```powershell
   git add -A
   git commit -m "release: v<版本>"
   git tag v<版本>
   git push origin main
   git push origin v<版本>
   ```
7. 在 GitHub 创建 Release，上传第 4 步的两个文件，正文粘贴 `CHANGELOG.md` 对应段落。
8. 校验 Release 下载链接可访问、文件名未被改写。

## 命名约定

- 安装包：`desktop-icon-backup_<版本>_x64-setup.exe`
- 便携版：`desktop-icon-backup_<版本>_portable.exe`
- 标签：`v<版本>`，例如 `v0.3.0`
- 提交信息前缀：`feat:`、`fix:`、`docs:`、`chore:`、`release:`

## 配置兼容

- `settings.json` 新增字段必须带 serde 默认值，保证旧配置可直接加载。
- 备份目录中的 `meta.json` / `layout.bin` / `registry.json` 结构变更时，需在 `CHANGELOG.md` 标注兼容性。
